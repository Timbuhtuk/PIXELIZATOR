# Pixelizator

Редактор пиксельных изображений для Windows x64: уменьшение, подбор палитры, выравнивание сетки, история результатов и экспорт. Интерфейс написан на WPF; обработка доступна также через CLI.

## Запуск

[Скачать последнюю версию](https://github.com/Timbuhtuk/PIXELIZATOR/releases/latest): `Pixelizator.exe` или `Pixelizator-win-x64.zip`. Консольная версия — `Pixelizator-cli-win-x64.zip`. Автономные сборки работают без установки .NET и без интернета.

Добавьте изображения кнопкой «Открыть», сочетанием Ctrl+O или перетаскиванием файлов. Главная страница показывает библиотеку с размерами и количеством результатов. Карточка открывает выбранный исходник в редакторе. При узком окне библиотека, настройки и предпросмотр перестраиваются в одну колонку.

Окно использует собственную тёмную строку заголовка с кнопками сворачивания, разворачивания и закрытия. Вернуться к библиотеке можно стрелкой в панели редактора.

Второй баннер «Создание иконок» открывает отдельный экран ICO: загрузка кнопкой или перетаскиванием, исходник/результат из редактора, выбор нескольких размеров (16–256 px) и произвольной стороны (1–256 px). Предпросмотры соответствуют выбранному масштабированию и способу вписывания. «Сохранить ICO…» записывает все размеры в один файл с прозрачностью. Ctrl+O открывает изображение для текущего рабочего экрана. Опция «Удалить фон» убирает однотонный цвет: автоматически по краям, белый или чёрный. Допуск 0–100% регулирует отличие оттенков; исходник не меняется, прозрачность видна в предпросмотре и сохраняется в ICO.

В редакторе доступны три режима:

| Режим | Назначение | Начальные параметры |
|---|---|---|
| Фон | Крупные цветовые области и общая композиция | K-Means LAB, автоматический выбор, шаг RGB 16 |
| Сцена | Формы, свет и цветовые переходы | K-Means LAB, автоматический выбор, шаг RGB 16 |
| Детали | Спрайты, контуры и прозрачность | Median Cut, без дополнительной палитры, весь кадр, порог покрытия 75% |

Размер, число цветов и другие параметры можно менять вручную. «Обработать» добавляет новый вариант в историю. Выравнивание сетки — отдельная операция с сохранением размеров и исходных цветов; «Ячейка сетки → 1 пиксель» сжимает выровненный результат без повторного квантования.

Предпросмотр сохраняет пропорции и увеличивает пиксели без сглаживания. Ctrl+колёсико меняет масштаб; прокрутка исходника и результата синхронизирована. Доступны шахматный, тёмный и светлый фон.

Верхняя лента хранит результаты текущего исходника, нижняя — исходники. Перетаскивание результата в нижнюю ленту создаёт независимый исходник для дальнейшей обработки. Крестик удаляет запись из библиотеки; внешние оригиналы и экспортированные файлы сохраняются. «Сохранить» экспортирует выбранный результат; для прозрачных изображений используется PNG.

Библиотека автоматически хранится в `%LOCALAPPDATA%\Pixelizator\Library`. При переносе на другой компьютер скопируйте эту папку отдельно. [Описание выравнивания и API](PixelArtAlignment/README.md).

## Структура проекта

- `DomainColorTest` — WPF-приложение; историческое имя проекта сохранено. Ресурсы интерфейса и иконка находятся в `Assets`.
- `PixelArtDownscale` — уменьшение изображений, квантование, палитры, обработка спрайтов и [создание ICO](PixelArtDownscale/ICO.md).
- `PixelArtAlignment` — выравнивание и сжатие пиксельной сетки.
- `Pixelizator.Cli` — консольный интерфейс к тем же алгоритмам.
- `PixelArtAlignment.Tests` — проверки алгоритмов, редактора, библиотеки и навигации.
- `Pixelizator.Cli.Tests` — интеграционные проверки CLI и обработки изображений.
- `artifacts` — локальные автономные сборки и временные результаты проверок; папка не загружается в Git. Готовые версии публикуются в GitHub Releases.

## Автоматические релизы

При слиянии pull request в `main` или прямой отправке коммита в `main` GitHub Actions собирает приложение на Windows, запускает проверки алгоритмов, WPF и CLI, затем публикует релиз. В самом pull request выполняются сборка и проверки без публикации.

Версия имеет вид `v1.0.N`, где `N` — номер запуска workflow; этот же номер записывается в версию EXE. Номера могут иметь пропуски из-за проверок pull request. Каждый релиз содержит `Pixelizator.exe`, `Pixelizator-win-x64.zip`, `Pixelizator-cli-win-x64.zip` и `SHA256SUMS.txt`, а описание изменений формируется GitHub автоматически. Ссылка «Скачать последнюю версию» всегда ведёт к актуальному опубликованному релизу.

Релиз появляется только после успешных проверок и загрузки всех файлов. Повторный запуск завершённой публикации сохраняет существующий релиз; незавершённая загрузка продолжается в черновике. Устаревшая сборка не публикуется, если в `main` уже появился более новый коммит. Ручной запуск доступен в **Actions → Build and release → Run workflow** для ветки `main`. Для публикации используется встроенный `GITHUB_TOKEN`, отдельные секреты не нужны.

Автоматизация обновляет релизы на GitHub. Установленную копию приложения пользователь обновляет скачиванием нового EXE; библиотека в `%LOCALAPPDATA%\Pixelizator\Library` сохраняется.

## Сборка и проверки

Нужен установленный .NET SDK 8 или новее с поддержкой Windows Desktop и .NET 8 Runtime для запуска проверок. Команда `dotnet` должна быть доступна в PATH. SDK и кэши пакетов не хранятся в проекте.

```powershell
.\Build-Standalone.ps1
```

Перед повторной публикацией закройте запущенный Pixelizator, чтобы Windows разрешила заменить EXE. Скрипт собирает решение, запускает проверки алгоритмов, WPF и CLI, публикует автономный EXE и создаёт ZIP. Если проверки уже выполнены, упаковку можно повторить с `-SkipChecks`.

Отдельные команды:

```powershell
dotnet build Pixelizator.sln -c Release
dotnet run --project PixelArtAlignment.Tests -c Release -- --ui --invariants
dotnet run --project Pixelizator.Cli.Tests -c Release
dotnet publish DomainColorTest -c Release -p:PublishProfile=win-x64
dotnet publish Pixelizator.Cli -c Release -p:PublishProfile=win-x64
```

Тесты создают собственные изображения и временные библиотеки, не используют пользовательскую историю или внешние наборы картинок. [Методика оценки выравнивания](PixelArtAlignment.Tests/README.md).

## CLI

CLI умеет уменьшать изображения, выравнивать пиксельную сетку и создавать ICO из PNG, JPEG, BMP, GIF и TIFF. Подробности формата и общий API: [создание ICO](PixelArtDownscale/ICO.md).

После публикации консольная версия находится в `artifacts/cli/pixelizator.exe`. В примерах `input.png` и `sprite.png` — ваши изображения, пути к ним нужно подставить самостоятельно.

```powershell
.\artifacts\cli\pixelizator.exe --help
.\artifacts\cli\pixelizator.exe input.png -o result.png --width 64 --height 64 --palette db32
.\artifacts\cli\pixelizator.exe align input.png -o aligned.png --cell-size 4
.\artifacts\cli\pixelizator.exe ico input.png -o application.ico --sizes 16,32,48,256 --resize nearest-neighbor
```

Без `--output` результат сохраняется рядом с исходником с суффиксом `_downscaled`. Для замены существующего результата нужен `--overwrite`; исходное изображение защищено от перезаписи.

| Высота | `--height` | 1–2160; **48** |

| Порог покрытия | `--alpha-threshold` | 1–100%; **50**; только с `--sprite` |
| Обрезка по горизонтали | `--crop-horizontal` | **center**, left, right |
| Обрезка по вертикали | `--crop-vertical` | **center**, top, bottom |

### Создание ICO

Команда `ico` создаёт многоразмерную иконку напрямую из изображения, не применяя палитру или повторное квантование. Псевдоним команды — `icon`.

```powershell
.\artifacts\cli\pixelizator.exe ico .\result.png -o .\application.ico --sizes 16,24,32,48,64,128,256 --resize nearest-neighbor --fit contain
```

`--sizes` принимает неповторяющиеся размеры 1–256 через запятую. `--resize` принимает `smooth` или `nearest-neighbor`; для пиксельной графики подходит второй вариант. `--fit contain` сохраняет пропорции и добавляет прозрачные поля, `cover` заполняет квадрат с центральной обрезкой, `stretch` растягивает исходник. Доступны общие флаги `--overwrite` и `--json`; без `--output` файл сохраняется рядом с исходником под именем `<имя>.ico`. Полная справка: `pixelizator ico --help`.

Числа — целые. Имена режимов нечувствительны к регистру; параметры поддерживают форму `--width=48`. Для пути, начинающегося с дефиса, используйте `--input=PATH` либо поставьте его после `--`. Справка: `--help` / `-h`, версия: `--version`. Запуск без аргументов показывает справку.

Размер результата не должен превышать исходник. Обрезка убирает остаток по каждой оси, чтобы ширина и высота стали кратными размеру результата; положение задаётся параметрами обрезки. `none` отключает привязку к фиксированной палитре, но предварительное квантование сохраняется. Число цветов задаётся через `--quantization-colors`; фактических цветов может быть меньше. DB16, DB32, NES, GameBoy и шаг RGB применяются позже и могут дополнительно сократить их число.

Без `--color-weights` все уникальные оттенки участвуют в квантовании на равных, как раньше. С флагом K-Means вычисляет средние с учётом числа пикселей, а Median Cut учитывает частоту и при разделении групп, и при вычислении среднего цвета. Начальные центры K-Means и число итераций остаются прежними. Для спрайтов в частоты входят только пиксели с альфой ≥128; полностью прозрачные и слабопрозрачные цвета исключены. Учёт частоты может помочь большим областям цвета, но редкие цветовые акценты могут потеряться. Это отдельная настройка от выбора представителя блока.

Значения ручного режима задают желаемые свойства **цвета, выбираемого внутри блока**, а не фильтры яркости и контраста всего изображения. CLI делит значения 0–100 на 100, как ползунки приложения.

Для прозрачных ИИ-спрайтов используйте `--sprite`. Он делит всю область на выходную сетку с дробными границами блоков, без обрезки. Покрытие блока считается с учётом исходной альфы; для выбора цвета и квантования используются исходные пиксели с альфой ≥128, без подмешивания чёрного фона. Выходной пиксель становится непрозрачным, если покрытие достигает `--alpha-threshold` и в блоке есть цвет для выбора. Порог 25% сохраняет больше края, 75% сужает силуэт. Этот режим не совмещается с параметрами обрезки или дизерингом. `--cropped-output` сохраняет весь исходник. Размер сетки задаётся вручную; автоматического поиска исходного размера пикселя или переупаковки кадров пока нет.

```powershell
.\artifacts\cli\pixelizator.exe .\sprite.png -o .\artifacts\skeleton.png --sprite --width 256 --height 128 --alpha-threshold 50 --palette none --preview-output .\artifacts\skeleton-preview.png --preview-scale 4
```

Чтение файлов использует тот же декодер, что и GUI (`Bitmap`); повреждённые или неподдерживаемые изображения приводят к ошибке. PNG и BMP сохраняют итоговые пиксели без потерь; JPEG может изменить цвета из-за сжатия.

## Примеры

Квантование в 128 цветов с учётом частоты и без дополнительной палитры:

```powershell
.\artifacts\cli\pixelizator.exe .\input.png -o .\artifacts\forest-weighted.png --quantization-colors 128 --color-weights --palette none
```

Для выключения учёта веса уберите `--color-weights`. Чтобы вернуть исходный размер палитры, задайте `--quantization-colors 64` или опустите этот параметр.

Ручной выбор цвета, обрезка справа снизу и палитра с шагом RGB:

```powershell
.\artifacts\cli\pixelizator.exe .\input.png -o .\artifacts\mountains.png --width 96 --height 64 --crop-horizontal right --crop-vertical bottom --palette step --palette-step 32 --quantization median-cut --block-mode manual --brightness 60 --contrast 70 --saturation 80 --edge 90 --threads 1
```

Сохранение обрезанного исходника и предпросмотра с увеличением в 8 раз:

```powershell
.\artifacts\cli\pixelizator.exe .\input.png -o .\artifacts\forest.png --cropped-output .\artifacts\forest-cropped.png --preview-output .\artifacts\forest-preview.png --preview-scale 8
```

Отчёт для скриптов:

```powershell
.\artifacts\cli\pixelizator.exe .\input.png -o .\artifacts\forest-json.png --json > .\artifacts\report.json
if ($LASTEXITCODE -ne 0) { throw "Обработка завершилась ошибкой" }
$report = Get-Content .\artifacts\report.json -Raw | ConvertFrom-Json
$report.dominantColor.hex
```

При `--json` стандартный вывод содержит только JSON: абсолютные пути, размеры исходника/обрезки/результата, эффективные настройки обработки, доминирующий цвет и время этапов. Ошибки всегда идут в стандартный поток ошибок (`stderr`). Отчёт выводится после успешного сохранения всех запрошенных файлов.

| Код возврата | Значение |
| --- | --- |
| 0 | Успех, справка или версия |
| 1 | Ошибка чтения, обработки или сохранения; существующий результат без `--overwrite` |
| 2 | Неизвестные/некорректные параметры, несовместимые настройки, повторяющиеся пути, неподдерживаемое выходное расширение или слишком большой итоговый размер |
